Field notes

What the work taught me.

Three practical lessons from building and operating these systems.

NOTE 01

Human approval is a workflow state, not a checkbox.

If a risky action pauses for review, the request, policy decision and reviewer outcome must remain traceable. That is why the control-plane reference treats approval as explicit state and preserves an audit event before execution.

Design consequenceNothing executes while approval is ambiguous.
NOTE 02

The 126s → 4s improvement did not come from a larger model.

The useful work was in the data path: query shape, indexes, connection pooling and concurrency behavior. Optimizing the expensive path first created a larger gain than changing the intelligence layer.

Design consequenceMeasure the bottleneck before choosing the fix.
NOTE 03

A model release needs reasons—not just a green button.

Accuracy, p95 latency, error rate and drift are evaluated together. When a release is blocked, the platform returns the violated policies so a team can act on evidence instead of guessing.

Design consequencePromotion gates stay explainable and reversible.
